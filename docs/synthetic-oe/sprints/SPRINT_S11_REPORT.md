## Findings

**1. The two-stage architecture beats every single-stage arm under stacking, and the effect holds on the blind
ladder** (T2, T5, T8). On `stacked_texto` K2 reaches item Acc@1 0.7271 against ColBERT's 0.4128: A1 +0.3143
[+0.2112, +0.3606], 39 concepts. On pooled L1 of `single_texto`: +0.0445 [+0.0188, +0.0870]. On `dose_texto`,
which no LLM arm had seen: +0.2758 [+0.2262, +0.3232] pooled, +0.4577 [+0.3941, +0.5202] at rung 5. From rung 2
up all 4 concepts have δ > 0; at rung 1 the difference is not detected (+0.0230 [-0.0363, +0.0835]). K2 falls
from 0.7896 to 0.7500 across the five rungs while ColBERT falls from 0.7666 to 0.2923 (T5). By the design's rule
the method contribution is **established on dev**. **Scope.** Every figure here is dev, and in-sample
with respect to the tolerant-key rule (S9's A7, fitted on dev) and to C's rules; their held-out reading is S12's.
The `phi4` prompt was chosen on OEB `resumen`, whose concepts sit on both sides of OE's split, so the LLM arms'
figures carry that exposure. Only the E3 ladder is blind for every arm.

**2. Ordering the family by ColBERT adds to K0; tolerance adds nothing detectable** (T8, T3, T1). A2: ordering
K0's tiers by ColBERT instead of catalogue position adds +0.0588 [+0.0371, +0.0715] on `single_texto` and +0.0692
[+0.0396, +0.0866] on stacked. A3: soft matching adds +0.0008 [+0.0000, +0.0036] on stacked, not supported; the
interval bounds the effect below 0.0036. The order is not most of A1's gain: descriptively (no registered
contrast), F1, which reads nothing and filters nothing, scores 0.4073 on stacked and K1 0.7263 (T1), so reading
the values and filtering on them carries most of the distance from ColBERT's 0.4128 to K2's 0.7271. T3 shows why: K1 and K2 put the gold in the
same top tier (0.7579 of stacked queries) and leave it in the run's top 100 almost always (0.9700, 0.9708). A
misread axis demotes the gold under both rules, and ColBERT then orders what is left.

**3. Restricting ColBERT to the concept: no equivalence shown, a small loss not excluded** (A5). F1 − ColBERT on
stacked is -0.0055, interval [-0.0287, +0.0053]: the lower bound leaves the ±0.02 band, so A5 is not supported;
the query-level interval [-0.0105, -0.0007] excludes 0. F1 inherits E5's Stage 1 (parent 0.9722 against ColBERT's own 0.9837, T1).

**4. The no-LLM route is strong on one edit and breaks under stacking** (A4, T1, T5). R2 beats `bm25_unigram` by
+0.5626 and `rules_valuenorm` by +0.5698 on pooled L1 of `single_texto`. Descriptively it is the best arm on
single queries (0.8825, K2 0.8325) and on verbatim ones (0.9970), but it falls to 0.4779 on stacked and from
0.8511 to 0.3224 across the ladder. Rules plus canonicalisation read one rewritten value; the LLM keeps reading
when several are rewritten. R2 against K2 is not a registered contrast.

**5. Reading values costs accuracy on verbatim queries** (A6, T3). K2 is 0.8483 on `texto_u` against ColBERT's
0.9993: -0.1511 [-0.1921, -0.0577], supported. `phi4` misreads 0.15 axes per verbatim query and the gold is in
the top tier for 0.8483 of them; R2 misreads none (0.00).

**6. By type, K2 − ColBERT is above 0 on `template_paraphrase` and the unit types; no arm reads
`synonym_label`** (T4). K2 − ColBERT: `template_paraphrase` +0.2403 [+0.1448, +0.3239], `unit_conversion` +0.1214
[+0.0051, +0.2855] (12 concepts), `unit_expansion` +0.0791 [+0.0335, +0.1217]; `synonym_label` -0.0263 [-0.0752,
+0.0311], with every arm between 0.6201 and 0.6889 there. Types differ in population and in which arms apply;
rows are not compared with one another, and no type is ranked above another. L2 rows rest on 5 concepts (‡).

**7. S9's A7 figure was partly catalogue-order luck** (T1). K0 reproduces S9's runs identically (T9, A4), but
read tie-free it scores 0.7728 on `single_texto` (as run 0.8157) and 0.6571 on stacked (0.6780).

**8. Coded `resumen` stays out of reach** (T1). On `resumen_u` every arm is near the floor at item level: K2
0.0961, ColBERT 0.0530, `bm25_unigram` 0.0239. Not tested.

**9. Cost** (T6). With extraction cached and family scores precomputed, the S11 arms retrieve in 0.0054–0.0324 s
per query (0.0059–0.0093 s on `texto_u`, `single_texto` and `stacked_texto`), except K0 on the E3 bases, which
generated live: 1.3021 s on `dose_texto`, 1.1029 s on `isolated_texto`. `bm25_unigram` takes 0.0011–0.0029 s
per query. A deployment also pays `phi4` (median 1.05–1.11 s per query on the five synthetic bases) and ColBERT query
encoding and family scoring: the cache builds took 0.295–0.439 s per query on the five synthetic bases, and more
on `texto_u` / `resumen_u`, whose reference runs encode all 35,422 dev queries. ColBERT alone takes 0.3705–0.4200 s
per query on `single_texto` and `stacked_texto`. Scoped as finding 1.

## What is now known to be wrong

1. **ColBERT scores are a function of the query alone.** They are not: the BGE-M3 server's query vectors depend
   on which texts share the request, which moves MaxSim (A2 states the measurement; it was not logged, so it is
   re-measured with a log before D-060 is decided). Every ColBERT run's near-ties are
   batch-dependent. No earlier figure is re-read here; S12's ColBERT and two-stage runs must fix their batching.
2. **The pipeline's Stage 1 is `dense_e5`'s rank 1.** Not for every query (A3): they differ on 8 to 86 queries
   per S9 base, so the design's A8 was restated.
3. **A text is a query of one base.** Not on the E3 ladder: dose and isolated sets share texts, which a store keyed
   by text conflated (A5).
4. **S9's A7 key-tolerant figure (0.8157 / 0.6780) measures the extractor.** Part of it is tie order (finding 7).
5. **Tolerance is where a two-stage design gains under stacking** (the design's rationale for A3). It adds nothing
   detectable; the gain comes mostly from reading values and filtering on them, and ordering adds to that (finding 2).
6. **A partial block computes the same MaxSim as a full one.** It does not on this GPU path (one fp16 step, 1b); the
   scorer pads.

## Deviations from design

- **A1** server address through `BGE_M3_API`. **A2** family scores built as a cache, in each reference run's
  blocks, with several candidate concepts per query. **A3** A8 restated against K0's Stage 1. **A4** K0 re-run under
  its own name on all seven bases (35 runs). **A5** one cache file per run, selected at `bind_queries`. **A6** T6's
  extraction timing fixed and the tables regenerated.
- Also, not in an amendment: the scorer pads partial blocks (work item 1b, `c3a937c`) and scores family by family
  (`a9e55b6`); both are implementation inside 1b and change no score (the build checks every compared score).
  Phase B's first attempt failed at load before writing any run (A5).

## What the next sprint inherits

  values and filtering on them (finding 2). A fine-tuned scorer is a candidate for K2's Stage 3, not only a
  single-stage arm; its room there is the within-tier order.
- **Open, not registered**: routing between R2 and K2 (R2 on one edit, K2 under stacking); a ColBERT Stage 1
  (F1's parent loss); `synonym_label`, which neither reading route recovers.
- **Debt**: `run_meta.json` of the LLM arms does not carry model digest or prompt SHA, so exit criterion 3 is not met
  (audit F1). T9 records the model digest from the determinism log and, since the extraction prompt is built in code,
  the SHA-256 of `src/pipeline/prompts.py` at every run commit; S12's runs must stamp both; `index/*/meta.json` omits the ML stack (H4).
